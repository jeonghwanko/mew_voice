# 뮤 보이스 브랜드 SSOT 관리

브랜드의 공식 값은 [brand.json](brand.json) 한 곳에서 관리한다. 이 문서는 값을 복제하지 않고 수정 방법과 적용 범위를 설명한다.

`identity.names`는 공식 명칭, `identity.nicknames`는 애칭이다. 앱 표시명과 마켓 제목은 공식 명칭을 사용한다. `brandId`와 이 디렉터리의 `mewvo`는 변경되지 않는 내부 키이며 사용자에게 표시하는 이름이 아니다.

## 무엇을 어디에서 관리하는가

| 정보 | 원본 |
| --- | --- |
| 영문·한글 이름, 포지셔닝 | `brand.json`의 `identity` |
| 합의된 제품 방향 | `brand.json`의 `productIntent` |
| 언어별 마켓 제목·슬로건·소개 | `brand.json`의 `copy` |
| 확정 아이콘·마켓 이미지·팔레트 | `brand.json`의 `assets` |
| 실제 구현 및 검증 상태 | [PROJECT_STATUS.md](../../PROJECT_STATUS.md) |
| 상세 기능 명세 | [SPEC.md](../../SPEC.md) |
| 패키지·번들·EAS·딥링크 식별자 | 기존 앱 설정. 브랜드명 변경과 별도 관리 |

`approved`는 확정, `approved-direction`은 합의된 목표, `draft`는 문구 제안, `pending-design`은 디자인 미확정이다. 목표와 문구가 있다는 사실만으로 기능 구현·스토어 게시 승인을 의미하지 않는다. `releaseReview`는 브랜드 합의와 출시 검토를 구분한다.

## 소비 방식

- 모바일: `app.config.js`가 원본 JSON을 직접 읽어 Expo `name`과 iOS `CFBundleDisplayName`에 적용한다. 현재 한국어 앱이므로 `identity.names.ko`를 사용한다. 글로벌 출시 시 OS 표시명 현지화 연결을 추가한다.
- 마켓 문구·이미지 제작: 원본의 해당 locale 값을 읽어 제작한다. 초안은 검토용으로만 사용하며 확정 후 `status`를 변경한다.
- 향후 웹·인앱 이름: JSON을 읽거나 이를 읽는 공용 adapter를 통해 참조한다. 현지화가 필요한 UI는 locale에 맞게 선택한다. 아직 웹·인앱 전체가 연결된 상태는 아니다.
- 기존 ‘우리 아이’는 반려묘를 가리키는 일반 문구나 탭 이름으로도 쓰인다. 브랜드가 아닌 문구를 전역 치환하지 않는다.

## 변경 절차

1. 이름·문구 변경은 사용자와 합의하고 해당 항목만 수정한다. 초안과 확정 상태를 구분한다.
2. `revision`을 증가시키고 `updatedAt`을 갱신한다. 변경 이유와 승인 범위는 Git 커밋 또는 PR에 남긴다.
3. 확정 에셋은 이 디렉터리의 `assets/` 아래 버전이 있는 파일명으로 저장한다. JSON의 경로는 저장소 루트 기준 상대 경로를 사용한다. 기존 파일을 덮어쓰지 않는다.
4. 제작 산출물에는 사용한 브랜드 revision·locale을 기록한다. 이미지 속 글자가 변경되면 해당 이미지를 다시 제작한다.
5. 아래 명령으로 Expo의 최종 표시명을 확인한다. 출력의 `name`과 `ios.infoPlist.CFBundleDisplayName`이 원본 한글명과 같아야 한다.

```sh
cd C:/Users/turbo08/mew_voice
npx expo config --type public --json
```

새 아이콘·스크린샷·마켓 업로드는 각각 별도의 적용 작업이다. 현재 JSON의 비어 있는 에셋은 기존 임시 아이콘을 공식 아이콘으로 승인했다는 뜻이 아니다. 초기에 만든 다른 이름의 이미지 시안도 공식 에셋에 포함하지 않는다.

## 에이전트 작업 규칙

브랜드 관련 작업 시작 시 이 문서와 `brand.json`을 먼저 읽는다. 새로운 브랜드명·슬로건·색상을 개별 코드나 문서에서 임의로 확정하지 않는다. 이전 기획 문서는 역사 기록이며, 브랜드 값이 충돌하면 이 원본을 우선한다. 글로벌 지원은 출시 목표이고 현재 구현된 언어 범위는 구현 상태 문서를 따른다.
