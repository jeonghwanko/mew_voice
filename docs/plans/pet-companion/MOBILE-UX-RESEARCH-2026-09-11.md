### 1depth: 하단 메뉴 4개

| 메뉴 | 사용자의 목적 | 첫 화면 구성 | 2depth |
| --- | --- | --- | --- |
| 오늘 | 지금 무엇을 하면 되는가 | 선택한 고양이, 주요 행동, 이어볼 결과 1건, 최근 기록 1~2건 | 야옹 생성, 관찰 상세, 빠른 돌봄 기록 |
| 대화 | 고양이와 상호작용하거나 기록에 질문하기 | ‘내 말을 야옹으로’, ‘고양이 울음 살펴보기’, ‘사진 살펴보기’, ‘기록에 물어보기’ | 각각의 작업 화면. 즉시 녹음하지 않고 사용자가 시작 |
| 기록 | 이전 일을 찾기 | 날짜별 목록, 기간·종류 필터, 기록 추가 버튼 | 관찰 상세, 돌봄 기록 상세 |
| 우리 아이 | 고양이와 계정 관리 | 선택한 아이 요약, 아이 관리, 설정 항목 | 아이 관리, 설정 |

‘오늘’은 재방문 요약, ‘대화’는 기능을 찾는 고정된 입구다. 첫 구현에서는 기존에 익숙한 4개 영역을 유지하고 중앙 생성 슬롯만 없애는 안을 추천한다. 추가로 ‘우리 아이’를 상단 메뉴로 옮긴 3탭 안을 탐색 테스트에서 비교할 수 있지만, 프로필·다묘 관리의 발견 가능성이 떨어지는지 확인해야 한다.

### 2depth와 상세 탭의 역할

```text
오늘 / 기록 ── 관찰 상세
                 ├─ 요약  : 가능한 해석 + 신뢰 수준 + 다음 행동
                 ├─ 단서  : 관찰 내용 + 다른 가능성 + 한계 + 원본
                 └─ 반응  : 실제 보호자 행동 + 고양이 반응 + 이력

대화 ── 내 말을 야옹으로       [녹음 → 생성 → 재생: 한 화면의 상태 변화]
     ├─ 고양이 울음 살펴보기   [입력 → 필요한 맥락: 작업 모달]
     ├─ 사진 살펴보기           [입력 → 필요한 맥락: 작업 모달]
     └─ 기록에 물어보기         [하단 입력창 + 질문/답변 + 근거 링크]

우리 아이 ── 아이 관리         [프로필 | 관리]
          └─ 설정              [일반 항목 목록, 불필요한 탭 없음]
```

여기서 2depth는 주요 탐색 단계다. 상세 탭 변경은 같은 기록의 보기 변경이며 새 화면을 push하지 않는다. 날짜·고양이 선택, 짧은 메모 편집은 시트로 처리한다. 긴 입력은 키보드를 고려한 전체 화면 모달로 확장한다. 삭제 확인이나 OS 권한 같은 필수 과정까지 억지로 두 번의 탭에 맞추지 않는다.

과거 근거 기록을 연속해서 여는 경우에는 상세를 무제한 쌓지 않는다. 원래 질문·기록으로 돌아갈 수 있는 근거 미리보기와 명확한 복귀 동작을 제공한다. 탭별 고양이·필터·목록 위치를 유지하며, 고양이 전환은 화면마다 반복된 칩 대신 동일한 헤더 선택기로 통일한다.

## 화면별 구체안

### 오늘: 대표 경험이 첫 화면에 보이게

상단은 한 줄 ‘모모의 오늘’과 고양이 선택. 첫 블록은 내 고양이의 작은 사진 또는 상태, 주 행동 ‘내 말을 야옹으로’. 최근 분석이 완료됐으면 ‘결과가 도착했어요’를 우선 블록으로 전환하되 야옹 기능 진입 위치는 계속 찾을 수 있게 유지한다.

사진·울음 관찰과 돌봄 기록은 작은 보조 진입 2개로 묶는다. 아래에는 최근 결과나 반응이 필요한 기록 1건, 오늘 기록 1~2건과 전체 보기만 둔다. 큰 브랜드 일러스트, 영어 장식 제목, 기록 횟수 통계는 첫 화면에서 내려놓는다. 이미지는 첫 경험과 나의 고양이 식별에 사용한다.

390×844, 기본 글자 크기를 첫 설계 기준으로 삼고 360×800과 320×568에서도 확인한다. 예산 예시는 상단 시스템 영역 48 + 헤더 56 + 핵심 경험 200 + 보조 행동 64 + 최근 기록 160 + 간격 48 + 하단 메뉴/안전영역 90 = 666 논리 단위다. **시안용 예산이며 실제 OS 측정값이나 고정 높이 구현 명세가 아니다.** 작은 화면에서는 최근 기록을 아래로 보내되 주요 행동은 보이게 한다. 큰 글자에서는 스크롤을 허용하고 글자를 줄이거나 자르지 않는다.

### 관찰 상세: 요약·단서·반응

상단은 뒤로 / ‘울음 관찰’ / 메뉴. 날짜·고양이·작은 미디어 미리보기 후 상세 탭을 배치한다. 사진 전체 크기는 단서 탭이나 확대 보기로 보낸다. 글로벌 하단 메뉴는 유지하고, 반응 CTA는 그 바로 위에 둔다.

| 탭 | 표시할 내용 | 조작 |
| --- | --- | --- |
| 요약 | 가능한 해석 1~2문장, 추정·단서 제한 등 신뢰 수준, 핵심 한계, 권장 행동 1개 | 하단 ‘반응 남기기’ → 같은 화면 반응 탭 선택 |
| 단서 | 실제 관찰, 대안 해석, 상세 한계, 사진·오디오 원본, 인용 기록 | 원본 재생·확대, 근거 미리보기 |
| 반응 | 행동 칩, 이후 반응 칩, 선택 메모, 기존 피드백 | 선택 완료 후 하단 ‘반응 저장’. 저장 성공 시 이력 갱신 |

‘관찰 단서’처럼 독립적인 내용을 펼쳐 읽는 것은 허용한다. 요약에 정확도를 뜻하는 가짜 백분율이나 확정된 고양이 발화를 만들지 않는다. 체험 기록에는 실제 AI 분석이 아니라는 표시를 유지한다.

상태별 기본 요약:

- 대기·처리 중: 단계와 ‘완료되면 기록에서 확인할 수 있어요’. 소요 시간을 모르면 진행률·남은 초를 만들지 않는다.
- 완료: 가능한 의미와 다음 행동. 반응 CTA를 즉시 제공.
- 판단 어려움: 부족한 단서와 다시 기록할 방법. 정상적인 결과 상태로 표현.
- 실패·취소: 원인에 맞는 재시도·동의 확인. 성공 결과와 같은 배지로 표시하지 않는다.

### 야옹 생성: 브랜드 임팩트를 한 동작씩

‘내 말을 야옹으로’ 화면은 작은 고양이 표현, 방향 표시 ‘내 목소리 → 놀이용 야옹’, 실제 녹음 상태, 하단 주 버튼으로 구성한다. 음성 입력은 이미 최대 6초이며, 숫자를 임의로 늘리지 않는다.

| 상태 | 주요 버튼 | 보조 조작 |
| --- | --- | --- |
| 준비 | 눌러서 말하기 | 짧은 사용 설명·닫기 |
| 녹음 | 녹음 끝내기 | 취소 |
| 생성 중 | 처리 상태 | 중복 요청 방지 |
| 준비 완료 | 야옹 들어보기 | 다시 말하기 |
| 재생 중 | 재생 멈추기 | 현재 재생 상태 |

파형은 실제 입력 강약, 햅틱은 녹음 시작·저장 완료 같은 조작 확인에만 사용한다. 마이크 요청은 사용자가 녹음을 시작할 때 한다. 권한 거부·백그라운드 중단·무음 입력에서 복구할 수 있게 한다. 생성음은 놀이용이며 의미 번역이 아니라는 짧은 문구를 재생 조작과 가까이 유지한다.

현재 야옹 생성은 로컬 임시 소리이고 기록·피드백과 연결돼 있지 않다. 첫 개편에서는 재생 후 독립적인 ‘반응 메모 남기기’ 돌봄 기록 진입까지만 재사용할 수 있다. ‘이 야옹에 대한 반응’ 자동 연결·음원 보관·공유는 데이터 모델과 보관 정책을 추가해야 하는 후속 기능이다.

### 기록·대화·돌봄 입력

- 기록: 일자별 작은 행, 선택된 필터 요약, 기간/종류 선택 시트. 사진·울음·돌봄을 정확히 구분한다. 현재 history의 관찰 행은 기본 문구·아이콘이 사진 중심이므로 AUDIO 표시도 바로잡는다.
- 대화: 기능 선택과 질문 작업을 분리. 질문 화면은 스크롤되는 메시지 영역과 키보드 위 입력창, 입력 보조 제안, 답변 안의 근거 링크로 구성한다. 예전 대화 목록은 별도 선택 시트에서 연다.
- 현재 서버 대화 계약은 질문별 Q&A다. 화면을 채팅처럼 만들 수 있지만, 실제 다중 턴 문맥·대화방이 생긴 것처럼 표현하지 않는다. 장기 대화방·스레드는 별도 계약 작업이다.
- 돌봄 기록: 종류 → 현재 시각 기본값 → 선택 메모 → 고정 저장 버튼. 종류 선택과 저장만으로 마칠 수 있는 짧은 흐름. 수정·삭제 후 원래 기록 목록으로 돌아간다.
- 프로필: 선택된 고양이부터 표시. 프로필과 관리로 나누고 삭제는 관리 안에 둔다. 실제 수정 API가 없는 항목의 편집을 구현된 것처럼 시안·출시에 노출하지 않는다.

## 임팩트: 처음 놀라는 순간과 다시 쓰는 이유

**첫 사용의 가치:** 첫 화면 → ‘내 말을 야옹으로’ → 녹음 → 생성 → 눌러 재생. 설명과 프로필 입력을 길게 요구하기 전에 제품의 구체적인 결과를 경험한다. 첫 진입부터 재생까지 중앙값 30초 이내를 파일럿 목표로 두되, 권한 확인 시간·합성 시간은 따로 측정한다. 달성했다고 주장하거나 사용자에게 보장할 수 있는 수치는 아니다.

**재방문의 가치:** 사진·울음 관찰 → 다음 행동 → 보호자가 기록한 실제 반응 → 나중에 해당 반응을 근거로 재열람·질문. 야옹 소리의 재미만으로 잔존을 가정하지 않는다. 관찰과 기록이 실제로 도움이 되는지를 별도로 검증한다.

예시 문구는 ‘어제 남긴 반응이 있어요 · 지켜봤어요 → 편안해 보였어요’. 해당 기록이 있을 때만 노출한다. 데이터가 없으면 빈 상태를 보이고, 기록 횟수를 친밀도·행복도·건강 점수로 해석하지 않는다.

첫 실행 화면은 기존 관찰 일기 설명을 실제 양방향 경험에 맞추되, AI 관찰과 놀이용 야옹의 차이를 명확히 한다. 로컬 야옹 체험은 계정 없이 제공하는 안을 추천한다. 현재 세션 게이트를 바꾸는 구현이 필요하다. 보관·서버 분석 동의는 해당 기능 진입에 맞추고 계정 복구·제품용 가입은 출시 준비의 별도 의존성이다.

## 구현 우선순위와 의존성

아래 효과 크기와 난이도는 코드 검토에 따른 상대적 판단이며 실측·일정 확약이 아니다.

| 순서 | 작업 | 기대 효과 | 난이도·의존성 |
| --- | --- | --- | --- |
| P0-1 | 공통 화면을 고정 헤더/본문/하단 작업 영역으로 분리 | 모든 주요 행동의 발견성과 키보드 대응 개선 | 중. Safe area와 Android edge-to-edge 검증 |
| P0-2 | 관찰 상세 3탭 + 고정 반응 CTA + 저장 피드백 | 결과 → 실제 반응 기록의 부담 감소 | 중. 기존 API 재사용 가능 |
| P0-3 | 야옹 상태별 주 버튼과 오늘 화면 압축 | 첫 상호작용의 가치 전달 | 중. 음성 생성 로직 유지, 권한·중단 회귀 검증 |
| P0-4 | 4탭, 대화 기능 진입, 상세 복귀 경로 | 기능 발견·위치 감각 개선 | 중~상. route 재구성·기존 딥링크 호환 |
| P1 | 짧은 돌봄 입력, 날짜 선택기, 목록 가상화, Q&A 입력창 고정 | 반복 사용과 입력 효율 개선 | 중. 기존 초안·충돌 처리 유지 |
| P1 | 관찰 cursor 소비, 전체 기간 필터, 정확한 집계 | 오래된 기록 발견·통계 신뢰 | 계약 확인 필요. 현재 모바일 관찰 훅은 items만 소비 |
| P1 | 계정 없는 야옹 체험·제품용 계정 흐름 | 첫 가치까지의 진입 부담 감소 | 세션 게이트·계정 복구 정책 |
| P2 | 야옹-반응 연결, 회고·공유, 다중 턴 대화 | 기록의 누적 가치 확대 | 서버 모델·API·동의/보관 정의 필요 |

화면 구현은 Expo Router와 RN StyleSheet를 유지한다. 공통 Screen의 기존 scroll 옵션만 끄는 방식으로 끝내지 않고 화면 종류별 본문을 구분한다. 목록에는 FlatList/SectionList, 입력에는 키보드 대응, 상세에는 로컬 탭별 본문과 고정 작업 영역을 둔다. 리스트를 일반 ScrollView 안에 중첩하지 않는다.

일반 상세는 해당 하단 메뉴의 stack 안에 두고 탭 상태를 유지한다. 녹음·촬영·신규 입력은 독립적인 modal로 제공한다. 여러 메뉴에서 같은 관찰 상세를 열 때는 공통 상세 컴포넌트를 재사용하고 진입 맥락을 보존한다. 기존 `/observations/:id` 등 외부 링크의 정규 경로와 앱 내부 stack 연결을 설계한 뒤 route를 옮긴다.

## 검증 계획과 완료 기준

먼저 보호자 6~8명의 정성 테스트를 제안한다. 신규·기존 사용, iOS·Android, 다묘 가정을 포함한다. 이 인원으로 개선율의 통계적 확신을 주장하지 않는다. 현재 화면과 제안 시안의 순서를 번갈아 제시하고 대표 작업을 수행하게 한다.

| 작업 | 측정 | 시안 통과 목표 |
| --- | --- | --- |
| 앱을 보고 용도 말하기 | 첫 5초 후 설명, 번역으로 오해하는지 | 입력/결과를 스스로 설명. 오해 발견 시 문구 수정 |
| 야옹 만들기 | 올바른 첫 클릭, 첫 재생까지 시간·권한 실패 | 홈 첫 화면에서 시작 버튼 발견 |
| 관찰 결과의 이유 찾기 | 단서 탭 발견, 결과와 확실성 구별 | 도움 없이 단서·한계를 찾음 |
| 실제 반응 저장 | 상세 진입부터 저장까지 탭·시간·누락 | 기본 글자에서 조작을 찾기 위한 스크롤 0, 1차 목표 4탭 이내(반응 진입·행동·반응·저장) |
| 과거 기록 수정 후 복귀 | 원래 필터·위치 유지, 저장 내용 확인 | 홈으로 강제 이동하지 않음 |

첫 파일럿에서는 기존 기준선을 수집하고 다음을 비교한다. 산업 평균을 임의의 목표로 사용하지 않는다.

- 첫 가치 도달률: 첫 세션 사용자 중 야옹 재생을 시작한 비율. AI 관찰 완료·조회율은 별도 퍼널로 집계.
- 반응 기록률: 관찰 결과를 본 사용자 중 24시간 안에 실제 반응을 저장한 비율. 결과별 중복 집계 방지.
- D7 핵심 행동 잔존: 최초 핵심 행동 코호트 중 7일째 기록·관찰·재생·질문 중 하나를 수행한 비율. 야옹 유입과 관찰 유입을 나눠 봄.
- 작업 성공: 저장 오류·권한 복귀 실패·중복 제출·오입력 비율. API 대기 시간과 UI 탐색 시간을 분리.
- 체감 가치: ‘결과를 이해했는가’, ‘다시 쓸 이유가 있는가’의 짧은 질문. 단순 체류 시간 증가는 성공으로 간주하지 않음.

제안 이벤트는 `entry_viewed`, `meow_record_started`, `meow_ready`, `meow_play_started`, `observation_viewed`, `detail_tab_selected`, `feedback_saved`, `checkin_saved` 등이다. 내부 QA·체험과 실제 계정 데이터를 분리하고, 분석 이벤트에는 원본 사진·소리·자유 입력 내용·고양이 이름을 싣지 않는다. 현재 이벤트 수집이 구현·검증됐다는 뜻은 아니다.

실제 개발 완료에는 custom dev client에서 작은 화면·큰 글자·키보드·화면 읽기·뒤로가기·초안 복원·마이크 거부/중단을 확인한다. 터치 영역은 플랫폼에 맞게 충분히 확보하고 탭 선택 상태를 음성으로도 전달한다. 타입·lint·테스트·Android export는 코드 변경 후 모바일 지침대로 수행한다.

이번 산출물은 조사와 제안이므로 앱 빌드·테스트는 실행하지 않았다. 클릭 시안의 고양이·관찰·반응은 모두 설명용 가상 데이터이며 녹음·AI·실제 저장 기능을 제공하지 않는다.
