## 1. 방향

`apps/mobile`의 기존 실종 신고 앱을 새 고양이 이해·대화 앱으로 전면 교체한다. 기존 화면에 기능을 붙이는 리팩터링이 아니다. 사진·울음·행동에서 관찰 가능한 단서를 설명하고, 보호자가 실제로 한 행동과 이후 반응을 기록해 다음 답변에서 활용한다.

첫 검증 단위는 **고양이 등록 → 사진과 질문 → 분석 결과 → 반응 기록 → 다음 질문에서 해당 기록 인용**이다. 첫 공개 버전은 여기에 **녹음·짧은 영상·기록 기반 대화·기본 주간 요약·내보내기/삭제·학습 동의 관리**를 포함한다. 사진만 가능한 내부 버전을 공개 MVP로 오인하지 않는다.

원문의 목표·일정·가격은 검증 가설이다. 제품명, SDK 버전, 모델 공급자, 요금, 출시일은 확정하지 않는다.

### 스토어 정체성은 코드 교체와 별개

현재 설정은 iOS/Android `gg.pryzm.union`, Expo slug/scheme `findthem`, EAS 프로젝트 연결을 사용한다. 같은 앱의 업데이트인지 새 스토어 앱인지는 문서만으로 알 수 없다. 기본 개발은 로컬 mock/내부 개발 환경에서 진행하고, 앱 식별자를 임의로 바꿔 제출하지 않는다.

- 기존 스토어 앱 유지: 앱 이름·아이콘 변경, 기존 token 재검증, 새 온보딩 키, 구 딥링크 안내, 기존 알림 진입 처리 및 구 사용자 업그레이드 테스트가 필요하다. 기존 신고 데이터를 새 앱에서 지우지 않는다.
- 새 스토어 앱: 새 package/bundle ID·scheme·EAS·OAuth callback·푸시 연결을 별도로 구성한다.
- 두 선택 모두 기존 모바일 코드는 전면 교체한다. 브랜드와 식별자 확정은 네이티브 배포 설정 단계의 결정 사항이다.

## 3. 구현 구조 제안

현재 저장소의 Expo + React Native + expo-router, StyleSheet, TanStack Query, SecureStore 구조를 기술 출발점으로 삼는다. 기존 버전은 Expo 54 / RN 0.81.5이나 새 프로젝트의 지원·호환 버전은 착수 시 공식 문서와 실제 dev build로 확인한다. 루트 workspace에 가입시키지 않는다.

```text
apps/mobile/
  app/                 # auth, onboarding, tabs, capture, observations/[id], pets, settings
  src/core/            # API client, auth, storage, query, errors
  src/ui/              # tokens, buttons, cards, inputs, empty/loading states
  src/features/
    pets/ capture/ observations/ conversation/ feedback/ history/ reports/ privacy/
  assets/              # 새 브랜드 에셋
```

백엔드는 기존 Express 안에 `/api/pet-companion/*`를 신설하는 안이다. 아직 등록된 API가 아니며 구현 시 충돌 확인 및 앱 레지스트리 갱신이 필요하다. 인증은 기존 계정 기반으로 연동하되 새 기능의 객체별 소유권을 서버에서 검사한다. 무거운 미디어 분석·대화 생성·요약·내보내기·삭제는 BullMQ를 사용한다. 모바일에는 provider secret을 두지 않는다.

기존 `Pet`은 공개 지도용 `isVisible`, 위치, 문자열 나이 등을 포함한다. 새 사적 기록을 그대로 넣지 않고 `CompanionPet` 도메인을 별도로 설계한다. 기존 펫을 가져오는 기능은 명시적인 사용자 선택과 소유권 검증을 거치는 후속 범위다.

### 데이터 모델

| 모델 제안 | 핵심 책임 |
| --- | --- |
| CompanionPet | owner, 종, 이름, 확인된 정보, AI 추정 정보, 각 정보 출처 |
| Observation / Context | petId, 촬영 시각, 질문, 상황, 입력 종류, 품질, 처리 상태 |
| Media | private object key, MIME/길이/크기, 보관 기한, 삭제 상태 |
| Inference | 관찰, 후보, 근거, 신뢰 수준/이유, 모델·프롬프트·스키마 버전 |
| Feedback | 실제 행동, 이후 반응, 확인 시각, 메모, 별도 만족도 |
| Conversation / Message | petId, observationId, 발화, 인용 observation IDs |
| Consent / DataRequest | 동의 종류·버전·변경 시각, 내보내기·삭제 진행 상태 |
| Summary / AnalysisJob | 기간별 기록 수/요약, job ID, 오류·재시도·사용량 |

공유 DTO와 enum은 `packages/shared/src`에 정의한다. AI 추정값을 보호자 확인값으로 덮어쓰지 않는다. 서비스 저장과 공통 학습 참여는 독립적이며, 학습 참여 기본값은 꺼짐이다. MVP는 검색 기반 개인화를 사용하며 공통 모델 재학습 파이프라인은 후속으로 둔다.

### 분석 파이프라인

업로드 요청 → 소유권/동의 확인 → private upload → 서버 MIME·용량·길이 검증 → 관찰 생성 → 큐 → 프레임/음성 전처리 → 품질 판정 → 필요한 맥락 1~2개 → 같은 개체의 이전 기록 조회 → 구조화 추론 → 스키마 검증 → 결과 저장 → 후속 반응 기록.

- 상태: `queued / processing / needs_context / completed / abstained / failed / cancelled`.
- 중복 제출은 idempotency key로 통합하고 quota도 중복 차감하지 않는다. 네트워크 복귀 시 서버 job 상태를 재조회한다.
- 모달별 지원을 기술 실험으로 검증한다. 사진에서 소리를 관찰했다거나 무음 영상에서 울음 패턴을 분석했다고 만들지 않는다.
- 미디어 URL은 공개 uploads URL 대신 만료되는 접근 링크를 사용한다. 사람 음성 전사는 기본 제외한다.
- 검색·인용·벡터화에도 owner/pet 필터를 강제한다. 현재 기록 이후의 데이터를 과거 기억처럼 가져오지 않는다.
- 삭제 시 작업을 취소/무효화하고 진행 중 worker가 결과를 다시 생성하지 못하게 한다. 원본·썸네일·프레임·임베딩·요약·캐시를 추적하며 완료 여부를 검증한다.
- 보관 기간과 학습 철회 적용 범위는 설정 화면에 실제 구현에 맞게 표시한다. 이미 학습된 모델에서의 완전한 제거를 약속하지 않는다.

## 5. 검증 및 출시 기준

- 모바일 typecheck, lint, unit tests, Android export와 양 OS custom dev client 실기기 흐름을 검증한다. 카메라·녹음·오디오 인터럽트·앱 백그라운드·업로드 중단·권한 설정 복귀를 포함한다.
- API는 소유권 침해, 동의 변경, 중복 과금/작업, 삭제와 worker 경합, 데이터 격리를 집중 검증한다. shared 변경에 대한 기존 웹/API 소비자 회귀 확인도 포함한다.
- AI는 관찰 정확도·근거 없는 문장·판단 보류율·개인화 전후·모달별 실패/지연/비용을 측정한다. 다른 동물·가정으로 평가를 분리하고 개인화는 과거→미래 시간 순서를 지킨다.
- 원문의 파일럿 가설: 첫 분석 완료율 ≥70%, 후속 행동 기록률 ≥30%, 첫 주 3회 이상 기록한 가정 ≥30%. 각각 시작 사용자, 완료 분석 건, 첫 주 관찰 가능한 참여 가정을 분모로 기록하고 표본 수를 함께 보고한다. 정확도나 시장 검증 완료로 해석하지 않는다.
- 건강 점수, 확정 감정 번역, 인간 말→고양이 울음 의미 전달은 출시 범위에서 제외한다. 결과와 공유 문구에는 추정 표현을 유지한다.
- 공개 전 기록 내보내기/삭제, 오류 신고, 사용량 제한, provider 장애 시 판단 보류, 운영자의 접근 통제를 검증한다.
