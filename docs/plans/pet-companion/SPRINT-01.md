# Sprint 01 — 오늘의 10초 돌봄 기록

2026-09-10 · 구현 및 검증 중. 10만 DAU 성장 계획의 첫 개발 범위다. 공개 출시와 사용자 검증은 별도 게이트다.

## 이번에 만드는 경험

선택한 고양이 → 오늘 화면 → 사진 없이 돌봄 기록 → 기록 확인·수정·삭제. 사진 관찰에는 보호자가 실제로 한 행동과 반응을 칩으로 덧붙인다. 돌봄 기록을 건강 진단이나 AI 해석으로 바꾸지 않는다.

- 전역 고양이 선택을 홈·기록·촬영·대화에 적용한다. 계정/체험 모드별 저장값을 복원하고 유효하지 않으면 현재 목록의 첫 활성 고양이를 사용한다. 새로 등록한 고양이를 선택한다.
- 선택 변경 시 다른 고양이의 사진·대화 결과를 계속 표시하지 않는다. 돌봄 초안은 계정과 고양이별로 분리한다. 미디어 원문은 초안에 넣지 않는다.
- 돌봄 종류는 PLAY(놀아줬어요), MEAL(식사를 챙겼어요), NOTE(메모 남기기), CHECKED(특이사항 없어요). NOTE의 메모만 필수, 최대 500자다.
- 발생 시각을 편집하고 KST 기준으로 오늘을 구분한다. 미래 5분 초과 기록은 거절한다.
- 사진 없는 기록은 별도 CompanionCheckin에 저장한다. 저장에 AI와 미디어 큐를 호출하지 않는다.
- 오늘과 기록 화면은 실제로 불러온 해당 고양이 데이터만 표시한다. 사진이 없으면 일러스트를 사용한다. 조회 범위를 전체 누적 통계처럼 표현하지 않는다.

## 실제 서버 계약

공통 접두사 `/api/pet-companion`. 인증·소유권·활성 고양이 검사를 수행한다.

| 메서드 | 경로 | 요청 및 결과 |
| --- | --- | --- |
| GET | `/checkins?petId=&cursor=&limit=` | 최신 발생 시각/id 순서, `{items,nextCursor}`, 최대 50개 |
| POST | `/checkins` | `{petId,kind,note?,occurredAt,idempotencyKey}`, 신규 201·동일 재전송 200 |
| GET | `/checkins/:id` | 본인 활성 기록 |
| PATCH | `/checkins/:id` | `{version,kind?,note?,occurredAt?}`, 버전 증가·경합 409 |
| DELETE | `/checkins/:id` | `{version}`, 소프트 삭제 204·중복 삭제 204·경합 409 |

원래 생성 요청의 fingerprint를 보존하므로 편집 후 최초 요청을 재전송해도 중복 생성하지 않는다. 동일 키의 다른 본문은 409, 삭제한 기록의 재전송은 404다. 생성·수정은 보관 동의가 필요하고 철회 후에도 삭제할 수 있다. 내보내기는 활성 기록만 포함한다. 고양이 삭제 시작 시 기록을 숨기고 실제 고양이 삭제 시 FK cascade로 제거한다.

사진 관찰 피드백은 기존 API를 유지하며 행동·반응 칩과 ‘잘 모르겠어요’·직접 입력을 제공한다. **체크인 전용 후속 반응 모델, 사진 피드백 수정과 서버 중복 방지는 이번 범위에 포함하지 않는다.**

## 구현 순서

1. 데이터 계약과 migration, 서버 CRUD·권한·동시성 구현.
2. 전역 고양이 선택과 체험 모드 저장 계약 구현.
3. 오늘 화면·돌봄 입력·통합 기록·사진 반응 칩 연결.
4. 격리 PostgreSQL 통합 테스트, 모바일 타입·lint·단위 테스트, 번들 생성과 브라우저 과업 검증.
5. 실기기/파일럿 사용성 검증 후 다음 스프린트 결정.

## 검증과 출시 전 남은 게이트

- 격리된 PostgreSQL의 실제 HTTP 테스트: 인증·다른 소유자 접근, 동시 요청 6개→1행, 수정 경합, 철회 후 삭제, 삭제 재전송, 입력 검증, 동일 시각 페이지 이동, 내보내기·고양이 삭제를 검사한다. 큐는 mock이므로 Redis worker 실행 검증은 아니다.
- 모바일 테스트: 체험 저장 계약, 동시 저장, 수정·삭제, 선택 fallback, KST 자정·최근 기록 일수.
- 실기기 2종에서 강제 종료·권한 거부·약한 네트워크·글자 확대를 확인한다. 브라우저와 번들 검증으로 완료 처리하지 않는다.
- 5~8명 보호자의 설명 없는 기록 과업과 D7 재방문을 검증한다. 10초는 제품 목표이며 아직 사용자 측정 결과가 아니다.

## 다음 스프린트

R02의 이벤트 정의는 성장 계획의 설계 단계다. 분석 수집기·운영 대시보드·DAU 측정은 아직 구현하지 않았다. 먼저 원문 없는 핵심 활동 이벤트와 내부 QA 제외를 연결한 뒤 온보딩/프로필 사진과 저장 복구를 보강한다. 이후 가족 권한·초대, 주간 회고, 공유를 순서대로 검증한다. 가족·위젯·구독·음성/영상·10만 DAU 부하 검증은 별도 범위다.

선택값과 돌봄 초안은 계정별로 보존하며 계정 전환 때 다른 계정에 노출하지 않는다. 로그아웃 시 모든 영속 초안을 삭제하는 정책과 미디어 초안 완전 복원은 후속 작업이다.
