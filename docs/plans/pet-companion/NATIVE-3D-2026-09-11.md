# Native 3D loading failure — investigation

The TestFlight 1.2.0 (91) report shows the renderer error boundary while the rest of the home screen remains usable. Browser verification did not cover the native file-loading adapter.

## Confirmed dependency incompatibility

- Installed `@react-three/fiber` 9.3.0 native entry imports the root `expo-file-system` module.
- Its FileLoader reads `EncodingType.Base64` and calls `readAsStringAsync`; its embedded-image path also uses `cacheDirectory` and `writeAsStringAsync`.
- Installed Expo SDK 54 / expo-file-system 19 exposes the new API at the root. Legacy methods there throw at runtime, and legacy constants are not exported there.
- `expo-file-system/legacy` provides the expected contract. Existing app storage already uses that entry point.
- Fiber already patches numeric Metro asset IDs and React Native Blob handling. Those were initial possibilities, not the confirmed primary incompatibility.

The targeted fix should redirect only Fiber's native filesystem import, preserve the rest of the app's new FileSystem API, and preserve the V13 model and animation. Expo upgrading alone does not repair a consumer's obsolete import.

## Verification requirements

Exercise the native adapter rather than only the web GLTF loader; verify native Metro resolution, GLB byte loading, embedded texture writes, and web isolation. Run mobile typecheck, lint, tests and platform exports before producing replacement native binaries.

No connected Android device or configured local Android emulator was available during the initial investigation. A successful export or mocked native adapter test does not establish physical iOS GPU rendering. Record runtime verification and store build status separately.

## Implemented and verified

- Added a scoped Metro resolver redirect for Fiber native imports only; no dependency or asset version changes.
- Regression suite runs the installed native Fiber adapter against the real V13 GLB using mocked filesystem and native image decoding. Three embedded textures, the 24-bone skeleton and animation changes pass. Image decoding/GPU are not exercised by Jest.
- TypeScript and ESLint passed; Android and iOS Hermes exports completed in `apps/mobile/dist/native-3d-fix`.
- TypeScript now excludes generated export and market-image folders while retaining Expo's native/config exclusions; generated bundles were causing local typechecking to stall.
- Replacement signed build/upload: pending.
