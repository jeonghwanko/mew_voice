# 고양이 카툰 3D — 제작 방식 재설계

2026-09-11 · 조사 및 제안. 새 캐릭터의 외형은 아직 확정하지 않았다.

사용자 판단: **현재 `/original-cat/index.html` 시안은 제품에 사용할 수 없다.** 기존 시안은 실패 원인 확인용으로 보존하고 출시 후보에서 제외한다. 아래 내용은 제작자·공식 기술 문서를 조사한 결과와 이를 바탕으로 한 우리 앱의 설계 제안이다. 사용자 첨부 장화신은 고양이 이미지는 표정의 기준으로 유지한다. 아래 《The Last Wish》 제작 사례는 별도 작품의 제작 방식 참고이며, 첨부 장면의 제작 과정을 확인했다는 의미는 아니다.

## 1. 결론: 예쁜 표정을 먼저 만들고, 그 표정을 움직이는 3D를 제작한다

추천 방향은 **부드러운 그림책풍 카툰 3D + 정교한 얼굴 표정 + 고양이다운 반응 연기**다. 혁신의 중심은 렌더러를 교체하는 데 있지 않다. 캐릭터 원화와 표정 검증이 모델·재질·리그 제작을 이끌도록 순서를 바꾼다.

Three.js는 완성된 캐릭터를 앱에서 보여주고 반응을 연결하는 역할에 적합하다. 지금처럼 기본 도형 조합에 눈·털을 계속 추가하는 방식은 제품 캐릭터의 주된 제작 방법으로 중단한다. 모델 파일이 정상 로드되는 것과 캐릭터가 매력적인 것은 별도의 완료 조건이다.

## 2. 현재 시안이 실패한 이유 — 프로젝트 자체 진단

`assets/avatar/original/cat.mjs`, `sculpt.mjs`, 검토 화면 및 사용자 피드백을 바탕으로 한 판단이다.

| 관찰 | 왜 문제가 되는가 | 새 기준 |
| --- | --- | --- |
| 커다란 동공과 금빛 홍채 테두리가 얼굴에서 먼저 보임 | 시선·눈꺼풀·볼이 만드는 표정보다 눈 부품의 존재감이 강함 | 위·아래 눈꺼풀이 안구를 감싸고, 아래 눈꺼풀과 볼이 한 덩어리로 이어지는 얼굴 |
| 얼굴과 신체가 기본 도형의 조합으로 읽힘 | 전체 비율과 선의 흐름이 충분히 설계되기 전에 부품이 늘어남 | 정면·3/4·측면에서 모두 검증한 통합 조형 |
| 눈 전체의 세로 크기를 줄여 깜빡임 | 안구가 눌리는 느낌을 주고 눈꺼풀 연기를 만들기 어려움 | 안구 형태는 유지하고 눈꺼풀·볼을 표정용 변형으로 움직임 |
| 털 추가에 비해 인상이 크게 좋아지지 않음 | 미세한 표면 정보가 얼굴의 약점을 해결하지 못함 | 털 없는 단색 조형부터 통과, 털은 실루엣과 색 덩어리의 보조 |
| 일정한 주기의 호흡·고개·꼬리 흔들기 | 사용자의 행동과 연결된 의도가 약함 | 주의를 돌림 → 듣기 → 응답 → 안정의 짧은 연기 |

첫 내보내기 약 378KB에서 털·눈가 실험 후 현재 GLB는 5,251,092 bytes로 커졌다. 용량 증가는 품질 향상의 근거가 아니다. 이전 GLB 재로드 검증과 최신 파일의 검증 상태도 구분한다. 이번 리서치에서 최신 모델을 출시용으로 검증하지 않았다.

## 3. 제작 사례에서 확인한 것

### Blender Studio — 고양이는 표정 실험부터

《Pet Projects》 제작진은 2D 스케치와 3D 조형을 오가며 고양이를 설계했다. 극단적인 표정은 독립된 조형으로 빠르게 만들었고, 그림을 덧그려 수정한 뒤 필요한 메시 구조를 시험했다. 특히 일부 표정은 보는 각도까지 함께 설계했다. [Julien Kaspar·Vivien Lulkowski, Sculpting Pets, 2023-03-02](https://studio.blender.org/blog/pets-expression-sculpting/)

**우리에게 적용할 판단:** 먼저 정면에서만 예쁜 기본형을 완성해 고정하지 않는다. 기본 얼굴·눈 감기·궁금함·애교를 원화와 거친 조형으로 비교한다. 눈을 감았을 때도 귀엽고 3/4에서도 고양이로 읽히는지를 확인한 뒤 리토폴로지를 진행한다.

### Little Kitty, Big City — 귀여움은 움직임의 구체적인 성격

개발팀 애니메이터 Micah Breitweiser는 초기의 평범하고 사실적인 움직임이 밋밋했다고 설명한다. 이후 어린 고양이의 서툰 성격, 얼굴 blend shape, 코부터 꼬리까지 이어지는 포즈, 실제 고양이를 관찰한 귀·꼬리 움직임을 활용했다. [제작자 직접 기고, 2024-05-30](https://www.gamedeveloper.com/art/deep-dive-how-little-kitty-big-city-rejects-realism-to-achieve-authenticity)

**우리에게 적용할 판단:** 성격을 ‘귀여운 고양이’에서 **‘평소에는 편안하고, 말을 걸면 호기심 있게 다가오는 우리 아이’**로 구체화한다. 사용자 입력에 귀가 먼저 반응하고 시선과 고개가 뒤따르는 짧은 연기를 만든다. 미세 동작을 끊임없이 재생하는 대신, 정지와 반응 사이의 차이를 만든다.

### Puss in Boots: The Last Wish — 그림의 인상을 기술보다 먼저

VFX 슈퍼바이저 Mark Edwards는 스케치·애니메이션 테스트·배경을 함께 검토했다고 설명한다. 그림책 같은 화면을 만들기 위해 붓 터치가 음영에 나타나는 기법도 개발했다. 감정이 중요한 친밀한 장면은 부드러운 움직임을 택했고, 액션의 프레임을 의도적으로 끊는 연출은 선택적으로 사용했다. [AWN 제작자 인터뷰, 2023-02-23](https://www.awn.com/animationworld/mark-edwards-talks-visual-development-puss-boots-last-wish)

**우리에게 적용할 판단:** 영화의 털 시스템을 모바일에 그대로 옮기려 하지 않는다. 색 덩어리, 붓결, 눈과 볼의 형태, 감정이 읽히는 포즈를 우선 번역한다. 앱의 차분한 크림·세이지 배경 안에서 함께 검토한다. 사용자 참고 이미지의 애원하는 표정은 특별한 반응으로 쓰고, 평소에는 편안한 눈맞춤을 유지한다.

## 4. 우리 고양이의 아트 디렉션 — 제안

### 외형

- **눈:** 크게 하되 검은 원판을 붙인 인상을 없앤다. 위 눈꺼풀의 곡선과 기울기로 성격을 만들고, 홍채가 두꺼운 링처럼 읽히지 않게 한다. 하이라이트는 조명 방향과 일관되게 절제한다.
- **눈가 → 볼:** 아래 눈꺼풀이 부드럽게 볼로 흐르고, 볼이 작은 주둥이를 받치게 조형한다. 구형 볼 두 개를 붙이거나 윤곽선으로 접합부를 강조하지 않는다.
- **코와 입:** 작은 코, 짧은 주둥이, 약한 입선. 눈이 주인공이 되게 정보량을 줄인다. 모든 표정에 같은 웃는 입선을 붙이지 않는다.
- **몸과 실루엣:** 앉은 자세의 가슴·앞발·꼬리를 하나의 흐름으로 설계한다. 지나치게 아기 같은 비율로 고정하지 않고 실제 반려묘의 성묘 특징도 유지할 여지를 둔다.
- **털:** 볼·귀 끝·가슴의 큰 털 다발로 먼저 표현한다. 몸 안쪽은 방향성 있는 색칠과 약한 표면 결을 사용한다. 낱가닥 털은 얼굴의 읽힘과 실기기 성능을 확인한 뒤 필요한 곳에만 추가한다.
- **개체성:** 기본 주황 태비로 원화를 비교하되, 눈 색·이마 무늬·흰 주둥이·귀 형태를 바꿔도 같은 화풍이 유지되어야 한다. 실제 아이를 닮게 만든다는 제품 목표를 유지한다.

### 화면과 재질

추천은 부드러운 명암 단계와 손으로 색칠한 표면을 결합한 **그림책풍**이다. 대안으로 《Little Kitty, Big City》처럼 더 간결하고 선명한 게임풍을 비교한다. 두 스타일은 같은 얼굴·포즈·카메라·배경으로 비교해야 렌더링의 차이를 판단할 수 있다.

| 항목 | 제안 | 피해야 할 결과 |
| --- | --- | --- |
| 명암 | 큰 밝음·중간·그림자 영역, 얼굴 중심의 안정적인 조명 | 눈 밑과 주둥이에 얼룩처럼 끊기는 그림자 |
| 표면 | 손으로 그린 색 변화, 미세한 붓결 | 광택 플라스틱처럼 균일한 반사, 거친 노이즈 |
| 외곽선 | 필요할 때 실루엣 중심으로 얇게 | 눈·볼·코의 모든 부품을 검게 두르는 선 |
| 눈 | 선명한 시선과 부드러운 눈꺼풀, 제한된 반사 | 큰 금속 링, 과도한 유리 광택, 항상 최대 크기 동공 |
| 배경 | 기존 크림·세이지 안에서 얼굴을 돋보이게 | 모델·UI·배경이 서로 다른 화풍으로 보임 |

Three.js의 `MeshToonMaterial`은 `gradientMap`으로 카툰 명암을 제어할 수 있다. 공식 문서는 이 맵에 `NearestFilter`를 요구한다. 이는 명암 단계 비교의 출발점이며 얼굴 형태나 표정 문제를 해결하는 기능은 아니다. 부드러운 단계 경계·붓결·얼굴 전용 음영 제어는 별도의 재질 설계와 비교 실험으로 다룬다. [Three.js 공식 문서](https://threejs.org/docs/pages/MeshToonMaterial.html)

## 5. 앱의 차별점: 고양이의 반응을 인터페이스로

아래는 연구 결과를 바탕으로 한 **우리 앱의 새 연출 제안**이며 아직 구현하지 않았다. 실제 고양이의 감정을 판독했다는 표현과 AI 응답의 연출은 구분한다.

| 앱 상태 | 고양이 연기 | UI 연결 |
| --- | --- | --- |
| 첫 진입 | 잠깐 시선을 옮긴 뒤 보호자를 바라보고 천천히 눈을 감음 | 짧은 인사와 입력창 |
| 입력 시작 | 귀가 먼저 돌아오고, 고개를 조금 기울여 집중 | 입력 중인 질문을 유지 |
| 응답 대기 | 한 번의 생각하는 반응 뒤 편안히 기다림 | 진행 상태와 취소·실패 안내는 실제 UI로 표시 |
| 답변 도착 | 시선 복귀, 작은 몸의 전진 또는 앞발 반응 | 답변 펼치기·명시적 음성 재생 |
| 얼굴 터치 | 눈을 가늘게 뜨며 볼과 귀가 함께 반응 | 연출 피드백; 매번 큰 모션을 반복하지 않음 |

대화 홈은 정면·3/4에서의 매력을 최우선으로 설계하되 확대·축소와 측면 검토는 유지한다. 표정을 카메라 각도에 맞게 보정할 경우에도 측면에서 얼굴이 무너지지 않는지 검증한다. 단일 그림을 카메라에 붙여 놓는 방식은 자유 시점의 대체물로 삼지 않는다.

## 6. 실제 제작 순서와 통과 조건

아래 숫자와 조건은 우리 프로젝트의 제안 기준이며 업계의 보장된 공식이 아니다. 외형에 대한 사용자 선택과 기기 측정으로 조정한다.

| 순서 | 산출물 | 다음 단계로 넘어갈 기준 |
| --- | --- | --- |
| 1. 얼굴 디자인 | 실루엣과 눈매가 다른 원화 3안. 각 안의 정면·3/4와 96px 축소본 | 색·털·모자 없이도 구별되고, 사용자가 마음에 드는 안이 있음 |
| 2. 표정과 조형 | 선택안의 편안함·호기심·눈 감기·만족·놀람·애교 6표정. 원화와 거친 3D를 병행 | 눈가·볼 연결이 자연스럽고 정면/3/4/측면에서 인상이 유지됨 |
| 3. 반응 연기 | ‘말 걸기 → 귀 반응 → 눈맞춤 → 고개 기울임’ 4–6초 샘플 | 설명 없이도 나에게 반응한다는 의도가 읽힘 |
| 4. 모델 정리 | 표정 변형에 맞는 메시, UV, 눈꺼풀·볼 morph target, 귀·목·몸·꼬리 리그 | 표정 조합과 깜빡임에서 안구 관통·입 찢어짐·볼 접힘이 없음 |
| 5. 화풍 비교 | 같은 모델의 부드러운 그림책풍 / 간결한 게임풍 렌더 | 작은 홈 화면과 확대 화면에서 모두 매력적이며 UI와 어울림 |
| 6. 앱 통합 | GLB, 애니메이션 클립, 상태 전환, 옆 패널, 화면 이탈 처리 | 중급 Android/iOS에서 발열·프레임·메모리·복귀 확인 |

초기 성능 예산 제안은 본체 2–4만 triangles, 주요 텍스처 1K부터, 가시 draw call 15 이하, 중급 기기 안정적 30fps다. 표정 데이터·털·그림자는 실제 비용을 측정하며 배분한다. 이 숫자를 충족해도 시각 품질이 통과했다는 의미는 아니다. 모바일을 검증하지 않은 브라우저 렌더만으로 완료 처리하지 않는다.

## 7. 도구의 역할과 제작 현실

- **원화/이미지 생성 도구:** 매력적인 얼굴·포즈·색감 후보와 표정 시트를 빠르게 비교한다. 생성된 그림은 완성된 3D가 아니며, 여러 각도에서 같은 캐릭터인지 별도 검토한다.
- **Blender:** 선택한 디자인을 조형하고, 표정·메시·리그·UV를 제작한다. MCP나 Python 자동화는 반복 조작과 내보내기를 돕는 수단이다. 자동화 도구가 연결됐다는 사실만으로 얼굴의 미술적 완성도가 생기지는 않는다.
- **Three.js / React Three Fiber:** 완성된 GLB의 재질·카메라·표정·동작과 앱 상태를 연결한다. Blender에서 만든 임의의 셰이더 노드가 그대로 실행되는 것으로 가정하지 않는다.
- **필요 역량:** 원화에서 매력이 확정되지 않거나 3D에서 계속 손실되면 캐릭터 아티스트의 조형·표정 작업이 필요하다. 현재의 절차적 조형 결과로 영화급 캐릭터 제작 능력을 입증했다고 볼 수 없다.

Blender glTF 내보내기는 뼈대·shape key·오브젝트 변환 애니메이션을 지원한다. 기본 재질은 PBR 중심이며, 물리·조명·재질 등의 애니메이션이 모두 같은 방식으로 전달되지는 않는다. 따라서 표정과 골격은 GLB로, 카툰의 특수한 화면 표현과 상태 연결은 앱 렌더러에서 검증한다. [Blender 공식 glTF 문서](https://docs.blender.org/manual/en/5.0/addons/import_export/scene_gltf2.html)
