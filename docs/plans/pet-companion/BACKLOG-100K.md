## 우선순위

P0는 공개 가능한 핵심 제품, P1은 반복 사용·가족 검증, P2는 잔존 확인 후 확장이다. 담당은 실제 배정이 아닌 필요한 역할이다. 효과 점수나 RICE 숫자를 근거 없이 만들지 않고 선행 조건과 검증 가능성으로 순서를 정했다.

## 첫 개발 스프린트 — 2주 제안

범위는 **R02 + A01 + A02 + A04 + A05 + A06의 최소형**으로 고정한다. R01 인터뷰와 R03 시안은 병행한다. 이 스프린트 안에 가족·위젯·구독까지 넣지 않는다.

- 첫째 주: 개발 환경 연결·통합 테스트, 이벤트 정의, 고양이 선택 일관성, 일상 체크인 API/화면.
- 둘째 주: 오늘 화면, 반응 칩, 오류/초안 보완, 5~8명 과업 확인 및 실기기 핵심 경로.
- 결과물: ‘오늘 뭐 했지?’를 사진 없이 기록하고 다시 열어 확인할 수 있는 빌드, 실제 비용·지연 기준선, 다음 가족 기능 시안.
- 검증: unit 수 증가 자체가 목표가 아니다. 잘못된 개체 기록·중복·강제종료 복구·소유권·철회 등 실패 비용이 큰 경계를 검증한다.

## 가족 기능이 요구하는 아키텍처 변경

현재 CompanionPet의 ownerId 중심 검사를 단순히 OR member로 바꾸지 않는다. 명시적인 Household/Album, Membership, Invite, Role과 감사 정보를 설계하고 기존 소유자 기록을 1인 가구로 이관한다. 개인 보관 기록과 가족 앨범 기록을 구분할지 설계 단계에서 고정한다.

접근 정책은 단일 서비스 함수로 묶어 조회·미디어·분석·기억검색·내보내기·삭제·공유·알림 worker 모두에 적용한다. 삭제 책임과 가족 탈퇴 후 접근 범위도 통일한다. invitation의 링크 소지만으로 기록을 쓰거나 멤버가 되지 않도록 수락 절차를 둔다. 구현 전 기존 데이터 호환 migration과 롤백/복구 계획을 만든다.

## 보류 목록

공개 무한 피드·팔로워 랭킹, 출석 현금 보상, 구매몰/배송, 산책 지도, 확정 건강 점수, 품종/나이 정밀 추정, 상시 CCTV, 고양이 자극용 소리 재생, 강아지 동시 전면 개발. 10만 DAU 목표의 성공 조건을 검증한 뒤 필요에 따라 다시 우선순위를 매긴다.

## 개발 전에 필요한 운영 자원

파일럿 가정 모집, 행동 전문가 섭외, 브랜드·스토어 정체성, 실기기 2종 이상, 개발 전용 AI/미디어 예산 상한과 데이터 보관 정책이 필요하다. 사용자에게 즉시 모든 것을 결정하도록 요구하는 대신, 인터뷰·개발 환경·핵심 화면 작업을 먼저 진행하고 외부 비용 집행 또는 공개 출시 직전에 구체적인 범위로 결정한다.
